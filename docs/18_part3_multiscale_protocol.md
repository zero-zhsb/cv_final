# Part 3 多尺度实验协议

上一轮第 6+12 层融合提高了图像排序，但两个层共用同一 patch 网格。cashew 069 的两个标注区域合计占原图约 0.015%，融合仍漏检。本轮检验更细的采样能否帮助定位小缺陷，对应课程方向 A。实验设置和主要比较在查看本轮测试输出之前固定。

| 变体 | DINOv2 短边输入 | 输出 patch 网格 | 前景掩码 |
|---|---|---|---|
| 原 Part 2 | 448 | 448 网格 | 原官方 448 PCA |
| 单尺度控制 | 672 | 672 网格 | 官方 672 PCA |
| 多尺度融合 | 448 + 672 | 672 网格 | 官方 672 PCA |

三种变体均用冻结 ViT-S/14 最后一层。融合在原图坐标系中把 448 的特征双线性采样到 672 patch 中心，显式考虑官方预处理在下边和右边的裁剪。超出粗网格中心范围时取边缘值。对齐后逐尺度 L2 归一化，等权拼接，再进行精确最近邻搜索。近邻必须是同一个参考 patch。使用同一套参考旋转、20 张正常预留图的分位数阈值、top-1% 图像分数、原分辨率热图渲染及评估。高分辨率与融合均用 672 特征计算掩码。

## 复现

复用同一 VisA manifest（六类，1/2/4/8-shot，seed 0/1/2）、AnomalyDINO 与 DINOv2 固定提交、权重文件及原始 Part 2 run。完整矩阵各 72 配置，可以使用以下入口。服务器目录中的第三方依赖、权重和原 Part 2 run 可用只读访问方式复用。

```bash
cd /data/disk1/home/sshen560/cv_final_part3_multiscale
cv_part3_python=/data/disk1/home/sshen560/cv_final_member_b/.venv-b/bin/python
"$cv_part3_python" scripts/check_part3_multiscale.py \
  --data-root /data/disk1/home/sshen560/cv_final_data/VisA_pytorch/1cls \
  --output runs/part3_multiscale_gate.json
"$cv_part3_python" scripts/run_part3_study.py --study multiscale
```

后台任务启动后，可在本工作目录通过 `runs/part3_multiscale_status.json` 查看阶段。预检日志为 `logs/part3_multiscale_study.log`。正式推理和精确评价各有一份按变体命名的日志，例如 `logs/part3_scale672_inference.log`，每个 run 下也有 `run.json` 和 `evaluation_status.json`。

预检采用每类 8-shot 正常参考和一张正常校准图，检查有限输出、特征形状、两变体掩码一致和实际峰值显存。正式实验每次运行一个推理进程和一个评价进程，分别有 15% 与 10% 的 PyTorch 分配器上限。结果落在独立目录，原 Part 2 和多层实验可继续复核。

高分辨率热图的浮点分数跨度使原来的连续键直方图超过 10% 显存上限。多尺度实验改用按实际缺陷像素分数建立区间的精确 CUDA 评价器，逐批统计正常像素排在每个分数的下方或与其并列的次数。分数仍以原始 float32 键比较，并列计半分。该方法复用已保存的预测和原分辨率热图，显存分配取决于缺陷像素的不同分数数量。恢复流程跳过已完成的推理并接着评估。

## 评价

报告完整图像与像素 AUROC、每类指标、三个 seed 的均值和总体标准差，以及同一设备的时间和峰值 PyTorch 显存。用同尺度控制判断融合的额外贡献。完整精确评价覆盖测试集所有原分辨率图像和掩码，每张图使用原始异常距离。

完整矩阵结束后，使用同一共享 GPU 会话对三种变体另做效率抽样。在六类的 1/8-shot 条件下采用相同图像和重复次数，按类别与 shot 交替方法顺序。记录端到端图像加载和模型推理，热图渲染与评价另计。

补充分析预先固定小缺陷子集（掩码面积大于零且不超过原图 0.1%）。报告热图前 1% 像素覆盖了多少真实缺陷像素，并按类别与 seed 汇总。用经验测试 ROC 读取 FPR 不超过 5% 的漏检率，阈值只用于此对照指标，演示阈值照常由正常校准图计算。保留五个困难案例解释高分辨率的收益与失败场景。上一轮结果只用于提出假设，尺度和融合权重不根据测试成绩调整。
