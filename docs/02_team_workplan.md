# 成员 A / B 分工与逐步操作

目标：Pre 时展示真实可运行的 Part 1 和 Part 2、公平对比、困难案例及可复现仓库。本阶段暂不实现 Part 3，但保留未来入口。

## 共同先完成（M0）

1. 阅读 [课程要求](01_course_requirements.md)，确认六类别、shots、seeds、校准规则。
2. A 创建数据名单；B 检查它与官方读取方式一致。共同批准 `configs/course_protocol.json`。
3. 固定 [输出协议](04_experiment_protocol.md)，尤其是相对路径、异常图坐标、分数和指标定义。
4. 确认服务器的数据目录、GPU 与 Python 环境；A/B 分别 clone 到不同工作目录，共用只读数据，不在同一个工作目录切分支。
5. 把本文件各项建立成 GitHub Issues，填真实负责人、截止时间、验收证据。文档中的勾选清单是任务模板，不代表已经在 GitHub 创建 Issue。

## 成员 A：数据 + Part 1 + 评估 + 展示

### A1. 数据与名单（先于 B 的正式实验）

- [ ] 使用 spot-diff 脚本生成 VisA `1cls` 划分；不要重新随机划分测试集。
- [ ] 运行 `scripts/prepare_manifests.py`；工具检查六类目录、正常/异常测试图、缺陷掩码、校准集及参考集容量。
- [ ] 提交 `manifests/visa_1cls.json`，其中只含数据根目录下的相对路径。
- [ ] 与 B 检查 20 张校准图没有进入任何 reference；每方法使用同一 `manifest_id`。
- [ ] 交付：数据准备说明、各类数量、72 套 reference、共用测试清单。

验收：B 在自己的工作目录读取相同数据，可按名单定位每张图；名单生成两次结果完全相同。

### A2. Part 1 最小可运行版本

1. 先选一个类别，1-shot、seed=0，读取共享名单中的参考图和测试图。
2. 按上游几何规则缩放/裁剪；RGB 差分使用 [0,1] RGB，不把 DINOv2 的标准化张量直接拿来求颜色差。
3. 对每张测试图和每张 reference 算全图平均绝对差，取最小者为最近模板。
4. 计算通道平均绝对差图，固定高斯平滑参数，输出浮点异常图。
5. 以最高 1% 像素均值作为初版图像分数，记录取整规则（至少 1 个像素）。
6. 在该配置的 20 张校准图上计算分数，取 0.95 分位阈值；保存阈值与 reference/config 标识。
7. 输出原图、最近模板、差分热力图、图像分数、阈值、OK/NG。
8. 保留失败现象，先不做自编码器/配准扩展。未经测试前固定参数。

交付建议入口（待实现）：`scripts/run_part1.py`。实现后才把其确切命令写入 README。

### A3. 公共评估

1. 为两种方法读取统一 predictions 表与原始异常图。
2. 图像 AUROC 用原始连续 score；像素 AUROC 包含正常测试图。
3. 校验每个配置测试图完整且唯一、异常掩码存在、数值有限、尺寸/坐标一致。
4. 先逐类别算指标；每 seed 六类等权平均，再对三个 seed 算均值和总体标准差（ddof=0）。
5. 用小型已知例子检查：正确排序 AUROC=1、常数分数 AUROC=0.5、正常图参与像素评估。
6. 与 B 的官方结果交叉检查。发现差异时排查协议，保留两份原始结果，不静默覆盖或选更高值。

交付建议入口（待实现）：`scripts/evaluate.py`。再运行 Part 1 的全部 72 个配置。

### A4. 演示与图表

- 同一个界面切换 Part 1/Part 2，接收 B 的真实推理接口；若使用预计算结果，界面和讲解必须说明。
- Part 1 展示参考模板；两种方法展示原图、异常图、分数、阈值与 OK/NG；真值仅用于结果解释，不进入预测。
- 准备正常图、明显缺陷、细小缺陷、姿态/背景变化及实际失败例子；不强求某一种现象一定出现。
- 制作五个真实困难案例面板，保持同图、同裁剪、同叠加透明度并标注各方法色标。
- 录制离线备份，提交精选 PNG，视频放 Release 或按课程要求打包。

## 成员 B：服务器 + Part 2 + 汇总 + 效率

### B1. 环境和上游版本

1. 按 [服务器手册](03_server_runbook.md) 检查 GPU、驱动、PyTorch/CUDA 与剩余磁盘。
2. 在独立环境安装官方代码。固定 AnomalyDINO 提交号，保留许可证，记录自己的课程适配 diff。
3. 先验证 DINOv2 权重下载、特征提取及 CPU FAISS；不必第一天就解决 GPU FAISS。
4. 导出成功环境依赖与硬件信息，写进 README。仓库中不要提交 token、私钥或服务器密码。

### B2. 课程适配，正式跑分前必须完成

1. `src/utils.py:get_dataset_info` 的 VisA objects 限为六类；字典配置保持与类别一致。
2. 当前上游 `src/detection.py` 用排序切片 `[seed*shot:(seed+1)*shot]` 选图；不是 RNG 抽样。
3. 接入 A 的名单，读取对应 `references[category][shot][seed]`，校验数量与校准集不相交；将完整相对路径转换为上游需要的 reference 文件名。
4. 除课程规定的数据选择、导出与测量外，保持模型、agnostic masking/rotation、近邻与图像聚合方法不变。
5. 为 20 张校准图提供单独推理路径。**不能把它们放进记忆库，也不能混入 test/good 后参与最终 AUROC。**
6. 导出规范化 predictions 表、原始浮点图及配置；写明原始 patch 图与上采样图的区别。
7. 对官方单 seed 脚本输出与公共评估做核对，留存课程适配记录。

### B3. 单类别到全部实验

1. 第一轮只保留一个类别（例如 cashew），`--shots 1 --num_seeds 1`，并使用独立 run/tag。
2. 查看是否覆盖正常/异常图、是否只使用正确 reference、异常图位置是否合理。
3. 与 A 在相同样例上跑通端到端演示；双方确认接口后再批量。
4. 恢复全部六类，运行 1/2/4/8-shot、seed=0/1/2，共 72 个类别配置；失败的配置单独记录并补跑。
5. 记录每配置的数据名单哈希、代码版本、upstream commit、预处理、缓存策略与设置。
6. 模型/数据/代码变动必须用新 run/tag；官方脚本会跳过已有 metrics，不能把旧目录误当新结果。

### B4. 效率与结果汇总

- 同一设备，记录 CPU、GPU、精度、输入大小、CPU/GPU FAISS；CUDA 计时前后同步，预热后测量。
- 参考记忆库建立时间和每图推理时间分开；报告特征提取是否计入。
- 用 `torch.cuda.reset_peak_memory_stats()` / `max_memory_allocated()` 测量并注明统计边界；纯 CPU baseline 的 GPU 显存写 N/A，不虚报为同类测量。
- 缓存加速结果单独报告；无缓存的完整推理时间用于主效率对比。
- 汇总 Part 1/2 每类每 shot 三 seed 的均值±标准差，以及六类平均；制作 shot 曲线与五个困难案例说明。
- 向 A 提供不依赖真值的推理接口及各演示配置阈值。
